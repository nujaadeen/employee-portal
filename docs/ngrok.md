# Sharing the kind cluster with your team through ngrok

`scripts/kind-public.sh` puts the portal that runs on your laptop (kind, deployed with Helm) behind **one ngrok address**, so teammates anywhere can open it. It works while your laptop, the kind cluster and the tunnel are running.

```bash
ngrok config add-authtoken <your token>                   # once (dashboard.ngrok.com/get-started/your-authtoken)
KIND_DEPLOY=helm scripts/kind-up.sh                       # the cluster, if it is not up (Helm is required)
scripts/kind-public.sh up my-name.ngrok-free.dev          # your domain: dashboard.ngrok.com/domains (free accounts have one)
scripts/kind-public.sh check                              # tests through the public address
scripts/kind-public.sh stop                               # stop sharing (the tunnel only)
scripts/kind-public.sh local                              # stop sharing AND go back to the local-only set-up
```
Give your team: the address, the basic-auth user and password, and the demo password. They are in **`infra/public.env`** (git-ignored, mode 600, generated by the script, never printed). Demo users: `aisha.rahman` (Sales), `omar.haddad` (Manager), `lena.fischer` (HR), `priya.nair` (Engineer), `daniel.okoye` (Admin), `sara.qureshi` (Employee).

On the first visit ngrok's free plan shows a warning page: choose **Visit Site**. Then the browser asks for the basic-auth user and password, then the Baracel sign-in page appears.

## What "up" changes and why
| Change | Reason |
|---|---|
| One address: portal at `/`, API at `/api`, Keycloak at `/auth` | A free ngrok account has one domain. The issuer becomes `https://<domain>/auth/realms/baracel` for the browser, backend, AI service and Keycloak. TLS is ngrok's; inside the cluster the pods talk to Keycloak over its service name for token and admin calls (`config.internalAuthUrl`), and only the issuer string is public. |
| HTTP basic authentication in front of the web app (ingress) | Your choice: a shared user and password. It protects the web app. `/api` is protected by tokens, `/auth` must stay reachable for sign-in. |
| **New shared password for all demo users** (from `infra/public.env`) | The Keycloak sign-in page is on the internet. The old password `ChangeMe123!` is written in this repository. |
| Self-registration off; `portal-dev-cli` (direct password grants, dev only) off | Nobody outside should create accounts or request tokens with a password directly. |
| Keycloak's admin console and master realm answer only from 127.0.0.1 | They are never reachable through the public address (`kubectl -n baracel-portal port-forward svc/keycloak 8081:8080`, then http://localhost:8081/auth/admin for you). |
| Gitea is not published | It keeps running inside the cluster; links to Gitea in the app will not open for your team. |
| ingress-nginx trusts the forwarded headers | So Keycloak sees https and the real client address (needed for the admin-console rule). |

`scripts/kind-public.sh local` undoes it: password back to `ChangeMe123!`, registration and `portal-dev-cli` on, local hosts again.

## Limits and things to know
* Everything runs on your laptop: when it sleeps or the tunnel stops, the team loses access. The first AI answer can take a while (Ollama on your GPU); the embedding model and the Ollama bind address are the ones from `docs/kind.md`.
* ngrok free plans limit bandwidth and requests per month, and show the warning page above. They are per ngrok account, not per teammate.
* This is a **preview for colleagues, not production**: Keycloak runs `start-dev`, the demo seed data is loaded, the data lives in volumes on your laptop. Do not put real personal data in it.
* The shared password in `infra/public.env` is as strong as you keep it secret. Delete the file and run `up` again to generate new ones.
* Ollama must be reachable from the cluster (see `docs/kind.md`, "Finding the Docker host address for Ollama"), or switch the AI service to the fake provider with `KIND_LLM_PROVIDER=fake` when you create the cluster.

## Troubleshooting
| Symptom | Fix |
|---|---|
| `ngrok did not start` | The domain is not yours, or another ngrok session already uses it (`pkill ngrok` in your terminal, or stop it in the ngrok dashboard under Agents). |
| Sign-in loops or "invalid redirect URI" | `up` registers `https://<domain>/*` for the client `portal-web`. Run `up` again after changing the domain. |
| The backend answers 401 to a valid sign-in | The backend and AI service fetch the signing keys from the public issuer URL at first use: the tunnel must be up. `scripts/kind-public.sh status`. |
| `check` shows FAIL | Read the line: it names the expectation (for example the admin console must answer 403). |
